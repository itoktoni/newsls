- Type kepemilikan disimpulkan dari jumlah `rs_id` (boleh ditimpa `status_kepemilikan`):
  - tidak dikirim → **FREE**, `detail_id_rs = null`, **nol baris** `config_linen`
  - skalar / 1 elemen → **DEDICATED**, `detail_id_rs = rs_id`, 1 baris config

- Payload resmi dari user:
  `{"rs_id":75,"ruangan_id":168,"jenis_id":373,"supplier_id":1,"bahan_id":1,"status_cuci":"RENTAL","status_register":"REGISTER","rfid":["M2"]}`

Sudah diuji: DEDICATED, FREE, GROUP, GANTI_CHIP (→ `status_linen = KOTOR`) semuanya benar,
`config_linen` terisi sesuai type, lalu data uji dihapus.

⚠️ Catatan penting untuk user: payload contoh yang dikirim (`ruangan_id:1`, `jenis_id:1`, `rfid:"M2"`)
**gagal 422** karena `ruangan_id=1` dan `jenis_id=1` tidak ada di DB `bka`, dan `M2` sudah terdaftar.
ID yang valid untuk rs 75: ruangan `168/185/196/233/241-245/250`, jenis `373/374/376...`.
`jenis_id`/`ruangan_id` masih pakai rule `exists` — kalau mau dilonggarkan, tinggal bilang.

## Standard JSON API — `Plugins\Notes` (sore)

User minta bentuk JSON standar untuk SEMUA request API, meniru class `Plugins\Notes`
dari project lama. Dua keputusan yang diminta user:
1. **HTTP status SELALU 200** (persis legacy) — kode asli (401/422/404/…) hanya di `body.code`.
2. **Cakupan: semua endpoint API** + error handler global.

Envelope:
`{status: bool, code: int, name: string, message: string, data: mixed}`

`name` = jenis respons: `List` (data/index), `Data` (single/detail), `Create`, `Update`,
`Delete`, `Token` (login), `Validation`, `Error`.

### File baru
- `plugins/Notes.php` — `namespace Plugins;`, class `Notes`.
  - Konstanta gaya legacy (huruf kecil): `create/update/delete/validation/error/data/single/token`.
  - Method legacy dipertahankan apa adanya: `data() single() create() update() delete()
    error() validation() notFound() token() sentJson()`.
  - **Tambahan:** `failed($code, $message, $data, $name)` untuk kode selain 400/404/422
    (dipakai handler global: 401/405/429/500).
  - **Perbaikan dari legacy:**
    - `checkDebug()` pakai `config('app.debug')`, bukan `env('APP_DEBUG')` (env() jadi null
      kalau `config:cache` dipakai → log debug diam-diam mati).
    - `sentJson()` juga menganggap `is('api/*')` sebagai JSON, bukan cuma `wantsJson()`,
      supaya request tanpa header `Accept` tetap dapat Response JSON yang rapi.
    - `validation($message, $errors)`: param `$errors` (di legacy ada tapi TIDAK dipakai)
      kini dikirim lewat key tambahan `errors` → klien tetap tahu field mana yang salah.
      Ini perlu karena `sentJson` sengaja mengosongkan `data` jadi `[]` saat code >= 400
      (perilaku legacy). Key lama tidak berubah, jadi tetap kompatibel.
- `composer.json` — tambah PSR-4 `"Plugins\\": "plugins/"`.

### File diubah
- `bootstrap/app.php` — semua error request API lewat `Notes`:
  401 Authentication, 404 NotFound, 405 MethodNotAllowed, 429 Throttle,
  HttpException lain (mis. 403), 422 Validation (dengan `errors`), dan 500 catch-all
  (daftar paling akhir supaya tipe spesifik menang). Ditambah
  `shouldRenderJsonWhen(expectsJson() || is('api/*'))`.
  Handler web (flash + redirect-back) tidak berubah.
- `AuthController` — `Notes::token()` (login), `Notes::failed(401, …)` (login gagal),
  `Notes::delete()` (logout), `Notes::single()` (me), `Notes::update()` (updateProfile).
- `RegisterLinenController` — `Notes::create()` (store), `Notes::data()` (config);
  `use PayloadTrait` dihapus (tidak dipakai lagi).
- `app/Concerns/ControllerTrait.php` — cabang API pakai Notes:
  `views()` → `Notes::data()`, `respondView()` → `Notes::single()`, `getShow()` → `Notes::single()`,
  `response()` dapat param baru `$operation` ('create'|'update'|'delete') → dipetakan lewat
  helper baru `apiResponse()`. `postCreate/postUpdate/getDelete/postDelete` diupdate.
  Payload internal Action `{code,status,message,data}` TIDAK diubah — dipetakan di boundary.
