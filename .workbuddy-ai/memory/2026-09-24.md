## API download per RS — dari closure ke controller streaming

Permintaan user: "buat API untuk download dan optimalkan supaya tidak putus saat 12rb data",
lalu diarahkan melihat folder `andalan/` sebagai referensi kontrak.

Referensi legacy: `andalan/routes/api.php:72` (closure `download/{rsid}`) +
`andalan/app/Http/Resources/DownloadCollection.php` (bentuk response yang dibaca desktop).

### File baru
- `app/Http/Controllers/Api/DownloadApiController.php` (invokable)
  - Guard: `ctype_digit` → 404, `User::ensureRsAccess()` (403), RS tidak ada → 404,
    `detail_linen` kosong → `Notes::failed(404, 'Data Tidak Ditemukan !')`.
  - Response: `response()->streamJson()` dengan `data` = **generator** (chunk 2.000 baris,
    `DB::table` tanpa hidrasi model), `rs`, `ruangan`, `opname` dihitung sekali (kecil),
    plus key tambahan `total` (deteksi download terpotong di sisi desktop).
  - Anti-putus: `set_time_limit(0)`, `DB::disableQueryLog()`, `zlib.output_compression=0`,
    header `X-Accel-Buffering: no` + `Cache-Control: no-store`, `flush()` tiap chunk,
    `connection_aborted()` → stop, `JSON_INVALID_UTF8_SUBSTITUTE` (data legacy utf8mb3).
  - Aturan status meniru legacy: outstanding ada → status dari outstanding (tanggal = waktu
    generate); tidak ada → `BERSIH`; RFID tanpa baris `transaksi` → dipaksa `BERSIH`.
- `tests/Feature/Api/DownloadApiTest.php` — 5 test: auth 401, RS kosong 404, RS luar scope 403,
  kontrak legacy (termasuk `rs`/`ruangan`/`opname` + urutan key item + tanggal), dan
  **12.000 baris** (≈0,5 dtk, delta memory app < 32 MB, `substr_count` tanpa `json_decode`).

### File diubah
- `routes/api.php` — closure `download/{rsid}` diganti ke controller + `->whereNumber('rsid')`
  (URI & nama route tidak berubah, `RouteContractTest` tetap lulus).
- `AGENTS.md` §5.5 — kontrak + alasan tuning download didokumentasikan.
- `.workbuddy-ai/memory/MEMORY.md` — ringkasan endpoint.

### Keputusan penting
- Output tetap **streamed** (seperti legacy `streamJson`) supaya desktop langsung menerima data
  sejak chunk pertama; kelengkapan dijaga lewat key `total`, bukan dengan menahan payload
  sampai selesai (menahan payload = risiko timeout/putus yang baru).
- Envelope 404 untuk RS kosong (mengikuti AGENTS.md + route sebelumnya), bukan 400 legacy.
- `tanggal` diseragamkan `Y-m-d H:i:s` (legacy campur ISO8601 vs string).
- `routes/api.php` memang **sudah** tidak lolos `pint --test` sebelum perubahan ini
  (inline FQCN legacy); baris baru mengikuti gaya file tersebut. File baru 100% lolos pint.
